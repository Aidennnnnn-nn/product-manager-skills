# 属性物模型提示词规范

## 适用范围

用于为 IOT 属性物模型中的属性字段编写、检查和维护 AI 提示词，帮助 Agent 根据用户查询意图定位对应属性字段并理解查询条件。

本规范只适用于属性数据查询，不用于生成设置、控制或其他业务操作指令。

## 使用边界

属性字段提示词不替代以下内容：

- 属性物模型中的结构化定义
- 数据类型、单位、枚举值、数值范围和精度校验
- 用户功能权限和数据权限校验
- 查询服务的实际执行和返回结果

所有未确认的属性规则不得写入提示词。属性物模型发生变化时，应同步检查提示词内容。

## 信息来源

编写提示词前，应以当前属性物模型中已确认的信息为依据，包括：

- 属性名称和业务含义
- 所属设备或业务对象
- 所属数据侧或测量侧
- 数据类型、单位和精度
- 枚举值、数值范围和其他查询约束
- 与其他属性的区别或关联关系

缺少、冲突或无法确认的信息，应先补充确认，不得自行补造。

## 内容框架

| 内容项 | 编写要求 |
| --- | --- |
| 匹配场景 | 说明在什么业务场景、设备对象和指标语境下匹配当前属性；仅在用户意图明确指向该属性时匹配。 |
| 可匹配表达 | 列出当前属性的常用名称、同义表达和业务说法；仅保留与当前属性含义一致的表达。 |
| 混淆词汇 | 列出容易与当前属性混淆的其他指标或说法，并说明不得直接归并匹配。 |
| 模糊请求处理 | 说明用户仅使用笼统表达，或无法确定设备、测量侧和指标类型时，必须先向用户澄清。 |
| 查询条件解析与校验 | 依据物模型中已确认的数据类型、单位、枚举值、数值范围和精度解析查询条件；缺少必要信息、表达歧义或输入不符合规则时，先要求补充或修正。 |
| 结果反馈 | 查询结果以实际返回数据为准；未获得返回数据时，不得虚构、推测或承诺查询结果。 |

## 编写要求

1. 先说明匹配场景，再说明可匹配表达。
2. 明确列出容易混淆的其他属性或指标。
3. 对“功率”“温度”“状态”等无法唯一定位的笼统表达，要求 Agent 先澄清。
4. 查询条件的解析和校验只能使用物模型中已确认的规则。
5. 不得自行补造单位、范围、精度、枚举值或换算关系。
6. 提示词应写成一个连贯的自然语言段落，不展示上述框架标题。
7. 提示词只用于属性识别、字段定位和查询条件理解，不承担业务操作执行。
8. 查询结果必须以实际服务返回数据为准。

## 标准格式

```text
当用户在【业务场景】中，明确询问【设备对象】的【属性指标】时，识别并定位到“【属性名称】”。用户表达【可匹配表达】且目标对象明确时，可匹配本属性。若用户提到【混淆词汇】，或仅使用【无法唯一定位的模糊表达】，则先向用户澄清，不得直接匹配。按照属性物模型中已确认的数据类型、单位、枚举值、数值范围和精度解析查询条件；缺少必要信息或输入不符合规则时，先要求补充或修正，不得猜测。查询结果以实际返回数据为准；未获得返回数据时，不得虚构或承诺查询结果。
```

## 示例：逆变器 AC 侧输出功率

```text
当用户在查看逆变器运行数据，并明确询问设备交流侧实际输出功率这一指标时，识别并定位到“AC 侧输出功率”属性。用户表达“交流侧输出功率”“AC 输出功率”或“逆变器交流输出功率”等，且目标设备明确、上下文未指向其他功率指标时，可匹配本属性。若用户提到或可能指向“直流侧输入功率”“PV 输入功率”“负载功率”“并网点功率”“功率因数”等其他指标，或仅说“功率”“输出多少”而无法确定测量侧和指标类型，则先向用户澄清，不得直接匹配。查询结果以实际返回数据为准，单位和精度以属性物模型配置为准；未获得返回数据时，不得虚构或承诺查询结果。
```

## 质量检查

交付前应确认：

- 是否明确说明了当前属性的匹配场景
- 是否列出了可匹配的常用表达
- 是否列出了容易混淆的指标
- 是否规定了模糊请求的澄清方式
- 是否只使用了已确认的结构化规则
- 是否处理了缺少条件、歧义和非法输入
- 是否明确以实际返回数据作为结果依据
- 是否包含设置、控制或其他未授权业务操作语义
