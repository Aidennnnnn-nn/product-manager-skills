# 控制功能提示词规范

## 适用范围

用于为 IOT、储能、逆变器及其他设备的单个控制功能编写、润色、批量生成或检查 AI 提示词。本规范处理的是控制功能的自然语言理解规则，不替代 Control Schema、设备点表、权限校验或控制任务状态机。

## 信息来源

编写前优先读取当前控制项已有字段，例如：

- 功能名称和业务分类
- 功能标识符
- 数据类型、枚举值、数值范围、单位和精度
- 功能支持状态
- 参数依赖、前置条件和风险说明
- 控制结果与状态定义

只使用已确认的信息。缺少、冲突或无法确认的结构化字段应作为数据问题单独指出，不自行补造，也不靠提示词掩盖。

## 五维检查框架

五个维度用于起草和审核，不是最终提示词必须显示的标题。简单控制项可以合并表达；没有功能特有规则的维度不必重复通用系统规则。

### 用户意图

说明用户表达什么需求时应识别为当前控制项。

- 覆盖常见、明确且不会扩大边界的同义表达。
- 说明容易与其他控制项混淆的表达边界。
- 不因关键词相似就把不明确请求强行映射为当前功能。

### 参数值转换与校验

说明自然语言如何转换成控制项接受的值。

- 枚举型：写清业务状态与枚举值的对应关系。
- 数值型：写清单位、范围、精度以及相对表达的处理方式。
- 固定命令型：写清固定值，禁止接收其他值。
- 用户没有提供必要值、单位不明确或表达无法唯一转换时，先澄清，不猜测。
- 不创造源字段中不存在的枚举、默认值、范围或换算规则。

### 执行前提与风险

只描述当前控制功能特有的执行前提和风险，例如：

- 是否会中断设备运行或改变安全边界
- 是否需要用户在执行前明确确认
- 是否依赖其他控制项、模式或当前值
- 是否要求先读取当前值或按特定顺序执行

三码、权限、平台、在线状态等通用运行条件不写入单项提示词，由结构化配置和 IOT 运行时统一处理。

### 异常处理

写清当前控制项遇到不完整、歧义或非法输入时如何处理。

- 需要补充信息时，提出具体问题。
- 值超出范围或枚举无效时，指出允许值，不自动截断或替换。
- 前置条件不满足时，不发起控制，并说明缺少的条件。
- 不把“无法确认”表述成“设备不支持”，也不把“指令已发送”表述成“执行成功”。

### 结果反馈

只补充当前功能特有的结果判定方式。

- 区分待确认、已发起、设备已接收、设备已执行和执行失败。
- 需要状态回读才能确认效果时，明确以回读结果为准。
- 未获得最终设备结果时，不向用户宣称控制成功。
- 通用状态文案和控制流水规则由 IOT 统一维护，不在每条提示词中重复。

## 最终文本规则

- 默认写成一个连贯的自然语言段落，不显示“用户意图”“参数值转换与校验”“执行前提与风险”“异常处理”“结果反馈”等内部标题。
- 先说明识别条件，再说明值转换，随后写功能特有的确认或依赖条件，最后写异常与结果要求。
- 不重复功能标识符、寄存器、数据类型、三码、权限、平台和在线状态等已有结构化字段。
- 参数值映射虽然可能与枚举字段部分重合，但只要它帮助 AI 将自然语言稳定转换成目标值，就应保留。
- 使用明确动词，例如“识别为”“转换为”“询问”“拒绝执行”“以回读结果为准”。避免“妥善处理”“合理设置”“根据情况执行”等模糊表达。
- 不把识别结果、参数转换结果或指令发送结果描述为设备执行成功。
- 控制项名称保持与源表一致，不擅自改名。

## 常用写法

### 枚举开关型

```text
当用户要求【开启类表达】或【关闭类表达】【控制对象】时，识别为“【功能名称】”控制。【开启类表达】转换为【开启值】，【关闭类表达】转换为【关闭值】。用户未明确目标状态时，先询问用户；输入不能唯一转换为允许值时，不得发起控制。【功能特有的确认或结果规则】
```

### 数值设置型

```text
当用户要求设置或调整【控制对象】时，识别为“【功能名称】”控制，并从用户表达中提取【单位】数值。仅接受【范围】内、符合【精度】要求的值；用户未提供数值、单位存在歧义或使用“调高一点”等无法确定目标值的表达时，先询问用户，不得自行估算。【功能特有的前置条件和结果规则】
```

### 固定命令型

```text
当用户要求【典型意图及同义表达】时，识别为“【功能名称】”控制，并使用固定控制值【固定值】。该操作【功能特有风险】，执行前必须向用户确认。用户未确认或请求不明确时，不得发起控制。执行后【功能特有的结果判定方式】。
```

## 已确认示例

### 一键重启

```text
当用户要求重启、重新启动或一键重启设备时，识别为一键重启控制，并将控制值设置为 361。重启会中断设备当前运行，执行前必须向用户确认。用户未明确表达重启意图或未完成确认时，不得发起控制。执行后应区分指令已发送、设备已接收和设备已完成重启；未获得设备执行结果时，不得告知用户“重启成功”。
```

## 质量检查

交付前逐项确认：

- 是否能把用户表达唯一映射到当前控制项
- 是否准确说明必要的值转换，没有创造新值
- 是否处理缺值、歧义、越界和非法枚举
- 是否只保留功能特有的执行前提和风险
- 是否正确区分调用阶段和最终执行结果
- 是否删除结构化字段的机械重复
- 是否去掉内部框架标题并保持文本简洁连贯
