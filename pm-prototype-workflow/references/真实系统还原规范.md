# 真实系统还原规范

结论先行：只要能看到真实系统（可访问链接、截图、录屏），还原就是硬要求——先出元素对照清单，再画原型；对照不上的地方要么按真实写，要么登记为差异，不凭印象简化。

## 1. 触发条件

出现以下任一情况，本次原型按本规范执行：

- 用户给出真实系统链接、截图或录屏。
- 用户说「还原」「照这个做」「参考这个平台」。
- 已有原型被指出「还原度不够」。

## 2. 第一步：元素对照清单

先看真实系统，逐项记录，再动手画。缺项就是后续被返工的地方。

| 层 | 要确认的内容 |
| --- | --- |
| 壳层 | 顶栏高度、品牌区、语言/账号入口、左侧导航层级（一级/二级）、菜单项顺序与图标 |
| 层级 | 入口路径（如「项目列表 → 任务详情 → 创建任务」）、面包屑文案、页签位置与样式 |
| 工具区 | 搜索框宽度与占位、按钮顺序与主次、行操作的展开方式 |
| 表格 | 列数与列序、列宽比例、是否折行、空值写法、分页位置 |
| 组件 | 卡片尺寸与内部结构、弹窗宽度、提示条位置、进度条形态 |
| 图标 | 每个统计项/操作项的图标形状与含义、图标尺寸、语义色（绿/橙/红/蓝） |
| 文案 | 标题、副标题、按钮、空状态、提示语，逐字取真实文案，不改写 |

清单里确认不下来的项（如含义不明的统计数字），直接在交付说明写「口径待确认」，不要用自己造的解释填空。

## 3. 三档还原度

| 档位 | 含义 | 默认要求 |
| --- | --- | --- |
| 结构一致 | 页面层级、区块顺序、列与字段、按钮集合相同 | **必须** |
| 文案一致 | 可见文案逐字对齐真实系统 | **必须** |
| 样式一致 | 字号、间距、圆角、色彩、图标形状贴近 | 尽量，受项目 Token 约束 |

结构或文案对不上，等于没还原；样式可以按项目规范做有限调整，但不能把真实的多列压成一列、把真实的两级导航拉平。

## 4. 常见走偏

- **自造图标**：把「文件+加号」画成「人形」、把「文件+气泡」画成「机器人」。图标必须按 [图标库](图标库.md) 取真实形状。
- **自造统计口径**：卡片上的数字不知道含义就编一个（2/1/0 改成真实值 2/0/0）。
- **压缩信息密度**：真实系统一屏 7 列，原型为了好看改成 4 列。
- **无壳层片段**：只画内容区，不套顶栏与左侧导航，宽度失控。
- **凭记忆简化**：不打开真实系统，按上一版原型改。

## 5. 验收方式

1. 同尺寸并排：原型按 `1440` 宽截图，与真实截图同一区域并排比对，逐项看壳层、列宽、图标、文案。
2. 局部放大：图标、统计数字、状态标签等小元素放大到 2–3 倍核对，不靠缩略图判断。
3. 差异登记：没还原的项写进交付说明，注明原因（如「平台该图标为自研图标字体，原型用 Lucide 近似」）。

## 6. 交付说明模板

```text
还原范围：<入口路径>
对照结论：结构一致 / 文案一致 / 样式近似（差异 N 项）
差异清单：
- <元素>：真实为 <A>，原型为 <B>，原因 <C>
待确认：<口径或字段>
```
