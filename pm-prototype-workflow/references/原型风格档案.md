# 原型风格档案

## 选择与继承

先确认目标项目，再按用户当前选择、项目已确认选择确定档案。工作项目先查项目的 UI 规范与公共框架；已有明确来源时，说明采用的档案后继续，不每屏提问。没有来源或选择时只澄清一次。个人项目也不能自动替换已有设计系统。

- `project`：目标项目的视觉实现。不同项目的风格可以不同，不等于一套公司样式通用于所有工作项目。
- `personal`：Skill 内置的个人深灰科技风格。用户已选择后，读取[设计规范](个人风格设计规范.md)并复制[HTML 模板](个人风格原型模板.html)。

用户切换档案时说明当前范围的壳层和 Token 变化，不自动修改项目规范、业务语义、旧原型、冻结版本或外部设计文件。档案选择不改变静态/可交互形态、PRD 门禁或 Figma 授权。

评审画布、屏号、入口和流转规则为共用层，产品界面的风格属于档案层。禁止拿项目壳层配个人色板，或只把旧后台按钮改绿就视为个人风格。

## personal 档案执行规则

本节只约定执行顺序与边界，不定义视觉值。色板、字体、尺寸、圆角与间距一律以[个人风格设计规范](个人风格设计规范.md)和 `assets/个人风格Token.json` 为准；主 Skill 共用 UI 规则章节中标注的项目默认视觉值不适用于本档案，不在 personal 稿中混用。组件登记、状态矩阵与静态/交互边界见[个人风格 UI 与交互规范](个人风格UI与交互规范.md)。

### 适用与不适用

| 适用 | 不适用 |
| --- | --- |
| 用户本次明确选择 personal，或当前范围已确认选择后继承 | 项目已有确认 UI 规范或公共框架，且用户本次未覆盖 |
| 当前范围无项目设计系统事实源，用户确认采用个人风格 | 需沿用项目品牌、专用尺寸或团队交付规范 |
| 个人项目的探索性原型 | 仅因项目属于个人就替换其既有设计 |

选择 personal 只改变视觉层；业务语义、页面状态、流转、控件行为、图标资产、验收门禁、静态/可交互形态与 Figma 授权均按共用规则执行。

### 起稿与替换

1. 声明档案与事实源：根节点写 `data-style-profile="personal"`，清单 `source` 与 `template` 指向个人设计规范与模板；`tokens` 与 `checks` 留空，由自检读取 Skill 内置 Token。
2. 先形成页面状态、流转、控件与图标三张清单；清单之外的屏、箭头和控件不进入 HTML。
3. 从[个人风格原型模板](个人风格原型模板.html)整体复制起稿，不重写近似壳层；删除不需要的示例组件、样例字段与虚构数据，不为凑齐模板增加需求。
4. 按下方对照表只替换可替换槽，并记录「锁定壳层 / 可替换内容槽 / 本次允许变化」三列；锁定范围与允许变化同时以清单 `lockedAreas` / `allowedChanges` 的登记为准，未列入可替换槽的差异视为缺陷。
5. 按「HTML 与清单」补齐标记与非展示 JSON，再按「校验边界」执行严格自检、浏览器与视觉回读。

| 锁定（不得改） | 可替换（限本次需求） |
| --- | --- |
| 窄侧栏与品牌区、工作区页头、壳层 DOM 与渲染函数 | 业务文案、字段、数据与状态 |
| Token 中的色板、字体、圆角、控件尺寸、间距档位 | 当前菜单选中态、页面标题 |
| Lucide 图标资产与控件语义 | 主内容区的页签、筛选、列表、表单、弹窗组件 |

模板内菜单、表格、指标和示例对象只演示布局，不视为需求；组件独立样例屏不是产品功能。

### 版本与交付

- 静态模板只演示默认态。交互版沿用同一 DOM、Token 和档案标记，仅在已确认需求内补行为；控件样例不授权新增业务能力或交互分支，升级交互版不换档案。
- 本地交付目录与面向用户的文件优先中文命名，技术文件名受项目约束时沿用既有规范。档案、事实源、锁定 Token/壳层与允许变化记入交付清单，不写入产品界面。
- 历史原型与冻结版本不因本节规则回写或迁移；档案切换只影响当前范围。

## HTML 与清单

新建 HTML 根节点写 `data-style-profile="personal"` 或 `data-style-profile="project"`。同一 HTML 只用一个档案；对比两套风格时输出两个独立 HTML。静态和交互版均使用此标记。

将以下结构合并进现有交付清单；HTML 同时内联一份非展示 JSON，供机器核验。不得在产品界面写来源路径、档案说明或校验备注。

```html
<script type="application/json" id="prototype-style">
{
  "profile": "personal",
  "source": "references/个人风格设计规范.md",
  "template": "references/个人风格原型模板.html",
  "lockedAreas": ["侧栏", "页头", "控件 Token"],
  "allowedChanges": ["业务内容", "当前菜单状态"],
  "tokens": {},
  "checks": []
}
</script>
```

个人档案不在每份清单复制 Token，由自检读取 Skill 内置 `assets/个人风格Token.json`。项目档案的 source 和 template 改成真实项目来源；tokens 必须包含从来源提取的 CSS 自定义属性和值，checks 至少包含一项实际锁定壳层或组件的 selector、property、value。只抄模板示例或自己填一套预期值不能证明项目一致，仍须回读来源核对。

项目风格示例（只说明格式，不作为新的项目规范）：

```json
{
  "profile": "project",
  "source": "项目已确认UI规范.md",
  "template": "项目公共框架.html",
  "lockedAreas": ["导航", "顶部栏"],
  "allowedChanges": ["业务内容"],
  "tokens": {"--sidebar-width": "220px"},
  "checks": [{"selector":".sidebar","property":"width","value":"220px"}]
}
```

## 校验边界

- 新建或明确重画：`node scripts/audit.mjs 原型.html --strict --require-style`。
- 历史稿：原命令继续使用；未标档案不强制迁移。已有档案标记但 JSON 缺失或不匹配仍报错，不静默跳过。
- personal 检查内置 Token 与当前存在的标准组件；project 检查清单声明的 Token 与壳层，并要求声明的壳层存在。临时将预期值改成实际错误值不能替代修复。
- 自检覆盖声明、Token 与可测样式，不证明事实源权威、全部图标路径正确或所有业务规则完整；仍分别执行来源差异检查、浏览器检查和视觉回读。
- 可交互版沿用档案和 Token，只按已确认需求补行为。风格模板中的控件样例不授权新增业务能力或交互分支。
