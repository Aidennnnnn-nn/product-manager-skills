# 设计参考资料使用规范

## 来源原则

1. 用户提供的品牌规范、目标产品界面、精确 Figma 节点和已确认项目组件优先。
2. 没有项目级设计系统时，可从本文件列出的公开设计系统和 UI Kit 中选择 1-3 个匹配来源。
3. 设计参考用于组件、布局、密度和交互表达，不自动带入来源项目的品牌、业务对象或内容。
4. 不在 Skill 中保存私有 Figma 文件、内部资料库地址、临时下载链接或访问凭据。

## 匹配规则

- 移动 App 原型：优先 `Apple iOS / iPadOS UI Kit`、`Material 3 Design Kit`。
- 平板原型：优先 `Apple iOS / iPadOS UI Kit`、公开 iPadOS UI Kit。
- Web/SaaS 后台：优先 `Untitled UI`、`Ant Design`、`MUI`、`Simple Design System`。
- 企业中后台或运营系统：优先 `Ant Design`、`MUI`、`Untitled UI`。
- 设计系统或组件规范：优先 `Simple Design System`、`Material 3 Design Kit`。
- 线框和流程草图：优先公开 Lo-fi Wireframe Kit 和 Auto Layout 示例。
- 图表和信息图：优先公开图表组件库，并核对数据可读性和可访问性。
- 图标：优先项目已有图标库、Lucide、Material Design Icons 等可追溯来源。

## 来源记录

在 `原型数据.json`、HTML 注释或交付说明中记录实际使用的参考：

```json
{
  "materialSources": [
    {
      "name": "Ant Design",
      "usage": "企业中后台表格、筛选和弹窗结构参考"
    }
  ],
  "fallbackSources": []
}
```

使用补充来源时：

```json
{
  "fallbackSources": [
    {
      "name": "补充来源名称",
      "reason": "公开参考清单未覆盖该组件或视觉资产",
      "label": "补充来源"
    }
  ]
}
```

只记录实际使用的来源，不把浏览过但未采用的资料写入交付说明。

## 维护方式

- 新增长期复用的公开来源前，核对来源地址、使用许可、适用平台和维护状态。
- 私有设计系统只在对应项目内使用，不写入公开 Skill。
- 当项目规则与公开参考冲突时，以用户最新确认和项目规范为准。
