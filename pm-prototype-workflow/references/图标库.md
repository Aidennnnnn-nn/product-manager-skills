# 图标库

结论先行：原型图标只从白名单开源库取**原始路径**，按固定版本构建成 `assets/icons.js` 与 `assets/icons-domain.js`；Figma 侧使用该图标库在 Figma Community 发布的官方组件库（官方发布优先），两端版本对齐。禁止手写、临摹、混用多库、用 emoji 代图标。

## 1. 来源白名单

| 库 | 代码源（固定版本） | Figma 源 | 许可 | 适用 |
| --- | --- | --- | --- | --- |
| **Lucide（默认）** | `lucide-static@1.67.0`（unpkg / npm） | Figma Community「Lucide Icons（Full Collection）」`figma.com/community/file/983840782520404978` | ISC | 24 网格、2px 线性，最贴近后台控件 |
| Phosphor | `@phosphor-icons/web` | 官网提供的官方 Figma 文件 | MIT | 需要多字重（Thin→Fill） |
| Heroicons | `heroicons` | 官网链接的官方 Figma 文件 | MIT | 24 描边 + 20 实心两套 |
| Material Symbols | Google Fonts | Google 官方 Material Design kit | Apache-2.0 | 需要冷门图标时兜底 |

白名单外的图标一律不用：iconfont 随手拼、图标下载站、AI 生成图标、emoji 代替图标、照着截图临摹。

同一个原型只用一套图标库。版本必须固定，不写 `@latest`；Figma 社区文件通常滞后于代码包，**以代码版本为准**，并在交付说明里注明两端版本。

默认使用本 Skill 已构建的 Lucide 资产。只有项目已有可编辑图标库且项目规范明确要求时，才可使用其他白名单库；切换前必须在交付说明记录库名、版本、适用范围和切换原因。同一文件不得让不同执行者分别选择图标库。

## 2. 资产与方法

| 文件 | 内容 |
| --- | --- |
| `assets/icons.js` | 54 个基础 UI 图标，常量 `ICON` |
| `assets/icons-domain.js` | 12 个业务语义图标 + 3 个组合图标，常量 `ICON_DOMAIN` |
| `assets/icons.manifest.json` | 库名、版本、许可、网格、线宽、每个键的上游名与用途、组合关系 |
| `scripts/build-icons.mjs` | 构建脚本；**产物不要手改**，改脚本重跑 |

构建（推荐离线一次到位）：

```bash
curl -sSL -o l.tgz https://registry.npmjs.org/lucide-static/-/lucide-static-1.67.0.tgz
tar -xzf l.tgz
node scripts/build-icons.mjs --src ./package
```

没有本地包时去掉 `--src`，脚本逐个从 unpkg 拉取（带 3 次重试）。脚本会校验 `viewBox="0 0 24 24"`，不合规直接报错拒绝入库。

## 3. 用法

- 单文件原型把需要的常量整段粘进 `<script>`；不要用 CDN `<script src>`，评审稿必须离线可开。
- 尺寸走容器类，默认 16px；档位只有 `14 / 16 / 18 / 20 / 24`。禁止在 `<svg>` 上写 `width` / `height` 属性。
- 颜色走 `stroke="currentColor"`，由父级 `color` 决定；不给图标单独上色。
- 图标颜色继承所在控件与状态的语义色。旧后台参考色板不跨档案使用；个人风格取个人 Token，项目风格取项目规范，不另造图标配色。
- 常用尺寸：按钮内 15–16px，列表行操作 20px，卡片统计 14px，导航 15–17px，空状态/上传区 40–42px。

## 4. 已收录图标

**基础（`ICON`，54）**：导航 `menu / home / grid / dashboard / folder / panel / globe`；动作 `search / reset / refresh / plus / minus / circlePlus / close / check / edit / trash / copy / link / image / upload / download / external / more / filter / settings / bell / logout / user`；方向 `chevronDown / chevronUp / chevronLeft / chevronRight / back / forward`；内容 `file / files / list / listOrdered / alignCenter / table / calendar / clock`；反馈 `info / success / warning / error / danger / loading / sparkles`；视图 `eye / expand / collapse / sliders`。

**业务（`ICON_DOMAIN`，12）**：`filePlus / fileText / chat / chunk / vector / store / similar / tag / review / publish / scan / package`。

**组合（3）**：`fileChat / fileDone / fileWarning`。

完整键名、上游名与用途见 `assets/icons.manifest.json`。

## 5. 组合图标规则

Lucide 没有「纸张 + 角标」的成品，组合图标按同一套写法，新增组合沿用：

1. 底形取 `file` 的右下游离开口：`M11.2 22H6a2 2 0 0 1-2-2V4a2 2 0 0 1 2-2h8a2.4 2.4 0 0 1 1.706.706l3.588 3.588A2.4 2.4 0 0 1 20 8v3.4`，折角另起一段。
2. 角标取目标图标原始路径，包一层 `<g transform="translate(12 12) scale(0.5)" stroke-width="4">`。
3. **线宽在组上按 `2 / scale` 反向补偿**，缩放后仍是 2 个用户单位，与纸张一致。
   **禁用 `vector-effect="non-scaling-stroke"`**：它让角标在屏幕上恒定 2px，14px 图标下比纸张粗近一倍，整枚会糊成黑块。
4. 文字类角标（如 `message-square-text`）只留 2 行，3 行在 14px 下糊成一片。
5. 气泡类角标要垫一圈底色留白，否则和纸张断口线条连在一起。做法是在角标前插一条同路径的 `fill="var(--icon-halo,#fafafa)" stroke="var(--icon-halo,#fafafa)" stroke-width="7"`；宿主页面按卡片底色覆盖 `--icon-halo`（浅灰卡 `#fafafa`、白卡 `#fff`）。

## 5.1 状态图标的填充态

`success / warning / error / danger` 在实际界面里常以实心圆或实心三角出现。做法是**沿用 Lucide 路径、只改填充**，不另绘形状：

填充态必须**从库里的同一枚图标派生**，不能凭记忆重写路径（各版本 Lucide 的勾、感叹号几何不同，重写会与库版本对不上）：

1. 取库里 `success` / `warning` / `danger` 的内联路径。
2. 第一个元素（外轮廓 `circle` / 三角 `path`）追加 `fill="<语义色>" stroke="none"`。
3. 其余元素（勾、感叹号）追加 `stroke="#fff"`（浅底提示可用深色，如 `#ff323a`）。

| 形态 | 库键 | 外轮廓 | 内部符号 |
| --- | --- | --- | --- |
| 实心成功 | `success`（circle-check） | `fill="#25ce85"` | `stroke="#fff"` |
| 实心风险 | `danger`（triangle-alert） | `fill="#ff5868"` | `stroke="#fff"` |
| 浅底提示 | `warning`（circle-alert） | `fill="#ffb6bb"` | `stroke="#ff323a"` |

填充用品牌语义色，不引入第二套图形。

## 6. 新增与替换流程

1. 先在 Lucide 目录找语义最接近的图标；找不到再用白名单里的其他库，不自己画。
2. 取原始 SVG：`curl -sSL https://unpkg.com/lucide-static@1.67.0/icons/<name>.svg`。
3. 把 `键名 → 上游名 → 用途` 加进 `scripts/build-icons.mjs` 的 `GROUPS`，重跑构建。
4. 在原型里替换，按实际渲染尺寸截图复核（不看大图，看 14–20px）。
5. 若是一次批量替换，分批做，每批跑 `node scripts/audit.mjs` 并留截图。

## 8. 禁止

- 手写或临摹 SVG 路径（包括照着截图描）。
- 同一原型混用两套图标库，或同一页面出现两种线宽。
- 用 emoji、字符（`＋`、`×`、`→`）当图标。
- 用 CDN 引图标；改 `viewBox`；在 SVG 上写死宽高。
- 用 `‹`、`›`、`+`、`×`、`→` 等字符代替图标；分页、关闭、返回和方向操作必须使用登记的图标资产。
- 直接改 `assets/icons*.js` 产物（会被下次构建覆盖）。

## 9. 许可与署名

Lucide 为 ISC 许可，可商用、需保留版权声明。原型在 HTML 末尾注释里写一行：`图标：Lucide 1.67.0（ISC），https://lucide.dev`。

## 10. 双端同步

本 Skill 在 WorkBuddy 与 Codex 各有一份，**内容必须一致**：

- WorkBuddy：`~/.workbuddy/skills/pm-prototype-workflow/`
- Codex：`~/.codex/skills/pm-prototype-workflow/`（额外保留 `agents/openai.yaml`）

改动任一侧后，另一侧同步同样文件，并用 `diff -r`（排除 `agents/`）确认无差异。图标资产、脚本、规范文档一并在同步范围内。
