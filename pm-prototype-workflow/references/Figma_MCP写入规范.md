# Figma MCP 写入规范

## 适用范围

用于把已经确认的 HTML 原型通过远程 Figma MCP 写入既有 Figma Design 文件，并保留原生可编辑结构。本规范不用于浏览器点击、剪贴板导入或本地插件同步。

## 连接与权限

1. 优先调用 Figma MCP 的身份工具确认当前账号。
2. 如果当前会话没有暴露 Figma 工具，使用 `codex mcp list` 和 `codex mcp get figma` 检查连接状态；不要把模型供应商或模型中间站误认为 Figma MCP。
3. 远程 Figma MCP 使用独立 OAuth。不要在 Skill、脚本、日志或回复中写入访问令牌。
4. 身份未授权、目标文件不可访问或只有只读权限时停止，不尝试用页面操作绕过。

## 写入前读取

- 读取 MCP 提供的 `figma-use` 资源 Skill；创建完整页面或多分区视图时同时读取 `figma-generate-design`。
- 对非空参考节点优先调用 `get_design_context`，再用 `get_screenshot` 获取视觉证据。
- 页面级 `0:1` 可能是空 Canvas，`get_design_context` 可能返回“当前未选中图层”。此时用 `get_metadata` 或只读 `use_figma` 列出页面和顶层节点，不要循环猜测节点 ID。
- 目标页为空时，明确记录没有组件、变量或既有屏幕可复用，再按 HTML 定稿创建原生节点。

## 分段写入

复杂页面不要塞进一次大型调用。推荐顺序：

1. 创建根 Frame 和一级布局区。
2. 写入品牌区、导航或固定框架。
3. 写入主要内容区和重复组件。
4. 写入状态、按钮、说明和细节。
5. 回读截图和结构，执行最小修正。

每次 `use_figma` 调用都应：

- 使用明确的 `fileKey`。
- 说明本次只修改的范围。
- 返回 `createdNodeIds` 或 `mutatedNodeIds`，并返回关键容器 ID。
- 在后续调用中使用上一步实际返回的字符串 ID。
- 将新顶层节点放在现有内容右侧或其他明确空白位置；覆盖操作必须经过确认。

## 原生可编辑要求

- 页面、卡片和区块使用 Frame；结构相关的子项优先使用 Auto Layout。
- 文案使用独立 Text 节点，按钮底和按钮文字保持可分别编辑，或使用已有组件实例。
- 图标优先使用设计系统组件或真实图标资产；简单几何标识可以使用原生矢量或形状。
- 页面包含外部图片时，可用 `generate_figma_design` 生成临时视觉参考并取得图片填充；最终保留结构化可编辑版本，确认后删除临时参考。
- 不允许把整个 HTML 页面仅作为单张位图留在目标文件中。

## Plugin API 关键规则

- 颜色通道使用 0-1，不使用 0-255。
- 修改文本前先 `await figma.loadFontAsync(...)`。
- 文本自动换行时设置明确宽度，并使用 `textAutoResize = "HEIGHT"`。
- 用真实换行字符；当字符串转义不稳定时可用 `String.fromCharCode(10)` 连接行。
- `fills`、`strokes` 等数组重新赋值，不原地修改只读数组。
- `resize()` 在尺寸模式设置前调用。
- 切换页面使用 `await figma.setCurrentPageAsync(page)`。
- 所有异步 API 都要 `await`。
- 颜色透明度放在 Paint 或 Effect 的正确字段中，不把 `a` 塞进 RGB 对象。
- 失败脚本若声明未产生部分写入，仍应在重试前回读关键容器，避免重复节点。

## 参考设计与设计系统

- 先检查 Code Connect、目标文件现有屏幕以及可用组件、变量、文本样式和阴影样式。
- 目标文件为空或确无可复用资源时，允许按 HTML token 创建原生节点，不为证明缺失而进行无边界搜索。
- 参考文件的页面节点没有子图层时，说明可读取证据有限；以用户确认的 HTML 为结构与视觉事实源。

## 验证清单

视觉验证：

- 根 Frame 截图尺寸与预期一致，画面非空。
- 标题、正文、按钮和重复项没有重叠或裁切。
- 品牌色、背景、边框、圆角和阴影与 HTML 定稿一致。
- 图片和图标均正常显示。

结构验证：

- 根 Frame 名称、ID、宽高正确。
- 一级分区存在且命名清晰。
- 必需文案、按钮、状态和重复项目数量正确。
- 所有新增或修改节点 ID 已记录。

出现视觉问题时，先只读返回相关节点的 `id`、`name`、`type`、`x`、`y`、`width`、`height`、`characters` 和 `fontSize`，再定点修复。修复完成后重新获取根 Frame 截图并重复结构检查。

## 交付格式

```text
目标文件：<带 node-id 的 Figma URL>
根 Frame：<名称>
节点 ID：<id>
尺寸：<width x height>
关键节点：<名称与 ID>
验证：<截图回读、关键文案、层级和差异结果>
```
