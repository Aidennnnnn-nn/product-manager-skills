# 控件与空间规范

本参考用于 `pm-prototype-workflow` 的静态 HTML、可交互 HTML 和后续 Figma 原型。它统一控件的用途、结构、空间和适用状态，不规定项目品牌、色值、专用组件名称或业务内容。用户当前要求和项目已确认规范优先。

## 使用原则

- 静态与可交互原型使用同一套控件结构、尺寸和空间基线，不分别设计两套界面。
- 静态稿只展示本次评审需要的状态；行为、结果或恢复路径不同的状态分屏表达。
- 可交互稿在相同结构上实现适用的鼠标、键盘、焦点、加载、错误和恢复行为。
- 项目已有设计系统时复用其组件、变量和尺寸；本参考继续约束控件语义、状态区别、交互完整性和验收。
- 未有项目依据时使用本参考的默认空间档位，不用零散像素值修补布局。

## 1. 空间系统

### 1.1 基础档位

以 `4px` 为基础单位，默认使用以下空间 Token：

| Token | 数值 | 常见用途 |
| --- | ---: | --- |
| `space-1` | `4px` | 图标微调、紧密文字关系 |
| `space-2` | `8px` | 图标与文字、控件内紧密元素 |
| `space-3` | `12px` | 标签与控件、紧凑控件组 |
| `space-4` | `16px` | 普通字段间距、卡片内小分组 |
| `space-5` | `20px` | 中等字段组、内容分隔 |
| `space-6` | `24px` | 卡片内边距、表单分组、弹层内容 |
| `space-8` | `32px` | 页面区块、主要内容组 |
| `space-10` | `40px` | 大区块与主要流程节点 |
| `space-12` | `48px` | 页面边距、大区块分隔 |
| `space-16` | `64px` | 画布级留白或少量强调区隔 |

### 1.2 层级选择

按以下顺序判断空间，不跨层级混用：

1. **控件内部**：图标与文字通常 `8px`；单个控件内部的辅助元素使用 `4px` 或 `8px`。
2. **字段内部**：标签与控件通常 `8px`；控件与帮助或错误文字通常 `4px` 或 `8px`。
3. **控件组**：按钮组、单选组、复选组通常 `8px` 或 `12px`；独立字段之间通常 `16px` 或 `24px`。
4. **容器内部**：卡片、筛选区、弹窗和抽屉内容通常使用 `24px`；紧凑数据区可使用 `16px`。
5. **页面区块**：标题区、筛选区、主内容和分页之间通常使用 `24px` 或 `32px`；大区块可使用 `40px` 或 `48px`。

相邻元素的业务关系越强，间距越小。不能用分割线、背景色和大间距同时重复制造同一层级。

### 1.3 常用组合

| 场景 | 默认空间组合 |
| --- | --- |
| 页面内容区 | 页面内边距 `24px`；主要区块间距 `24px` 或 `32px` |
| 卡片/面板 | 内边距 `24px`；标题与内容 `16px`；内容组之间 `16px` 或 `24px` |
| 筛选区 | 内边距 `24px`；字段横向与纵向间距 `16px`；标签与控件 `8px` |
| 表单 | 字段间距 `16px` 或 `24px`；分组间距 `32px`；操作区与末项 `24px` |
| 表格工具区 | 工具与表格 `16px`；主要和次要操作间距 `8px` |
| 弹窗 | 头部、内容、底部操作区各自使用 `24px` 内边距；按钮间距 `8px` |
| 抽屉 | 内容区内边距 `24px`；字段间距 `16px` 或 `24px`；底部操作区与内容分开 |
| Toast/提示 | 图标与文案 `8px`；标题与说明 `4px`；操作与正文 `12px` 或 `16px` |

这些值是无项目规范时的默认选择，不覆盖项目已确认的组件尺寸。

### 1.4 密度与响应

- 同一区域只使用一种密度。普通业务页面采用默认密度；数据密集表格可以收紧行内空间，但筛选区、表单和弹层不随意同步压缩。
- 窄视口优先换行或改为单列，保持字段、操作和错误信息完整；不得为维持桌面同行布局而压缩到文字重叠或控件不可操作。
- 浮层接近视口边缘时允许翻转方向或调整位置，不改变触发器与浮层的归属关系。
- 空白用于表达层级，不为填满画布增加无业务意义的卡片、图表或说明。

## 2. 控件通用要求

每个控件至少明确：用途、结构、类型、尺寸、状态、文案、操作结果和异常反馈。不得只完成默认视觉。

- 控件状态按本次需求选择默认、Hover、按下、Focus-visible、选中、禁用、只读、加载、错误、成功或打开状态，不机械实现全集。
- 禁用表示当前条件下不能操作；只读表示可以查看和复制但不能修改；隐藏表示当前不展示。三者不得混用。
- 状态不能只依赖颜色，使用文字、图标、形状、位置或结构提供第二识别方式。
- 相同动作在页面、弹窗和抽屉中保持名称、类型和风险等级一致。
- 图标按钮必须有可识别名称或 `aria-label`；不常见图标提供 Tooltip。
- 控件切换状态时不应因边框宽度、字体粗细或提示出现造成无必要的布局跳动。

## 3. 操作控件

### 3.1 Button

- 默认高度 `36px`、圆角 `12px`；项目已有明确尺寸时复用项目值。
- 类型分为主按钮、次按钮、文字按钮、危险按钮和图标按钮。一个页面区块或弹层通常只有一个主按钮。
- 按钮名称使用“动词”或“动词 + 对象”，准确描述点击后的直接结果。不要用“确定”代替可明确命名的“保存”“确认导入”“删除”等动作。
- 图标与文字间距默认 `8px`；同组按钮间距默认 `8px`。
- 执行提交、上传、导入、切换环境等不可重复动作时进入加载态并锁定重复触发。加载期间保留按钮宽度，避免操作区跳动。
- 静态稿只展示本次需要评审的按钮类型和适用状态；交互稿检查 Hover、按下、Focus-visible、禁用和加载中的适用状态。

### 3.2 Switch

- 只用于切换后立即生效的二元状态，例如开启或关闭某项能力。
- 需要统一提交、存在三个及以上选项、需要比较后确认或切换具有高风险时，不使用 Switch，改用 Checkbox、Radio、Select 或带确认步骤的操作。
- 控件与标签间距默认 `8px`；标签整体可点击。状态文案优先描述当前状态或能力名称，不同时堆叠“开/关”和重复说明。
- 交互稿同步维护 `aria-checked`，支持键盘操作。异步生效时进入处理中状态，锁定重复切换；失败后恢复原状态并给出可观察反馈。
- 静态稿在行为不同的开启、关闭、禁用或失败状态之间按评审需要分屏，不能仅靠颜色暗示业务结果。

## 4. 表单控件

### 4.1 Input 与 Textarea

- Input 默认高度 `40px`、圆角 `12px`；Textarea 根据内容设置最小高度，不用单行输入框承载长文本。
- 结构按“标签 -> 控件 -> 帮助或错误文字”排列；标签与控件默认 `8px`，帮助或错误文字与控件默认 `4px` 或 `8px`。
- 占位符只提示输入形式，不代替字段标签、默认值或帮助说明。
- 新增、编辑表单的输入控件默认占位为“请输入”，选择控件默认占位为“请选择”，均不拼接字段名称；日期区间、上传等特殊控件按具体动作定义文案。
- 密码输入的显隐按钮不改变输入焦点；搜索框的清空和提交行为需要可判断。
- 字段首次展示不主动报空值错误；失焦或提交时校验，修正后及时移除对应错误。

### 4.2 Select 与 Combobox

- 单选 Select 用于从已知集合选择一项；可搜索的大集合使用 Combobox。选项少且需要直接比较时使用 Radio。
- 触发器默认高度 `40px`；弹层宽度不小于触发器，设置最大高度并在溢出时滚动。
- 空值代表不限时使用“全部”；必须选择具体值时使用“请选择”。占位不重复字段名称。
- 交互稿支持打开、选择、点击外部关闭、`Escape`、方向键和 `Enter`；选中、键盘活动项、Hover 和禁用项保持稳定区分。
- 多选使用标签或摘要回显，支持移除、清空、禁用项和超量折叠；选中一项后弹层默认保持打开。

### 4.3 Radio 与 Checkbox

- Radio 用于互斥单选；Checkbox 用于相互独立、可以同时成立的选项。Web 默认控件尺寸 `16 x 16px`。
- 控件与标签间距默认 `8px`；选项间距通常为 `12px` 或 `16px`；标签整体可点击。
- 覆盖未选、选中、Focus-visible 和禁用状态；Checkbox 在存在父子选择关系时按业务需要支持半选。
- 不用多个 Checkbox 模拟必须且只能选择一项的 Radio 语义。

## 5. 导航与选择

- Tabs 用于同一页面层级下的内容切换，不替代跨层级导航。当前项除颜色外还需有下划线、背景、字重或结构标识；交互稿使用 Tab/Tabpanel 语义并支持键盘移动。
- 分页用于数据集合翻页，结构固定为「页码组 + 每页条数 + 跳页」三段；页码序列、尺寸、状态、跳页边界和总量口径按 [列表与分页控件](列表与分页控件.md) 执行，不按单页临时造型。筛选变化后默认重置到第 1 页。
- 步骤条用于有明确顺序的多步任务，只表达当前位置、已完成和未开始；互斥分支不能画成连续步骤。
- 下拉菜单承载一组动作或入口，不承载复杂表单。高风险动作与普通动作分组或清楚区分。

## 6. 浮层与反馈

### 6.1 Tooltip 与 Popover

- Tooltip 只承载简短说明，不放必须阅读的规则、表单和关键操作。
- Popover 可承载少量信息或轻量操作；内容复杂、需要连续填写或确认时使用弹窗或抽屉。
- 交互稿明确触发方式、打开状态、关闭路径、边缘避让和焦点返回。

### 6.2 Modal、Drawer 与 Sheet

- Modal 用于阻断当前任务、确认高风险操作或完成短任务；Drawer 用于保留当前上下文的查看或编辑；Sheet 用于移动端或贴边的补充操作。
- 结构分为标题区、内容区和操作区。内容溢出时内容区滚动，标题和关键操作保持稳定。
- 操作区按钮间距默认 `8px`；主次与危险等级按动作风险确定，不按视觉对称随意交换。
- 交互稿检查初始焦点、焦点约束、遮罩或外部点击、`Escape`、关闭按钮、提交后关闭和关闭后的焦点返回中实际适用的路径。
- 静态组件评审只画组件本体；完整交互稿按真实产品行为展示遮罩和层级。

### 6.3 Toast、Banner 与行内反馈

- 字段问题使用行内错误；页面范围的重要状态使用 Banner 或结果区；短暂的系统结果使用 Toast。
- Toast 不承载需要用户记忆、比较或复制的大段信息；失败需要立即处理时提供明确恢复入口。
- 交互稿使用适当的 live region，避免同一结果被 Toast、Banner 和弹窗重复提示。

## 7. 数据与文件控件

- Table 保持表头、数据行、选择列、状态、行操作和分页对齐。行操作数量少时直接展示文字或图标按钮；只有项目规范或操作数量需要时使用“更多操作”。列宽档位、总宽策略与横向滚动时的操作列吸附按 [列表页装配与列宽](列表页装配与列宽.md) 执行。
- 状态标签用于简短状态识别，不承担完整错误原因；颜色之外保留文字。
- 空状态说明当前没有数据及可执行的下一步；加载状态不伪装为空状态。
- 上传区明确文件入口、格式和数量限制、已选文件、处理中、成功和失败等本次适用状态。处理中锁定重复上传和重复提交。
- Progress 用于可测量进度；无法测量时使用 Spinner 或处理中提示，不显示虚假百分比。Skeleton 只用于结构可预期的加载，不代替全部等待反馈。

## 8. 静态与交互原型差异

| 维度 | 静态原型 | 可交互原型 |
| --- | --- | --- |
| 结构与空间 | 使用正式控件结构和统一空间 Token | 与静态稿一致 |
| 状态范围 | 只展示本次需要评审的状态 | 实现本次流程可到达的状态 |
| Hover/Focus | 仅在其本身是评审重点时展示 | 对可操作控件实现适用状态 |
| 打开与关闭 | 用独立屏或局部演示表达 | 实现触发、外部或遮罩、`Escape`、关闭按钮等适用路径 |
| 加载与错误 | 用必要状态屏表达 | 实现锁定、防重复、失败恢复和结果反馈 |
| 键盘与焦点 | 不要求模拟完整行为 | 检查适用的键盘操作、初始焦点和焦点返回 |
| 数据提交 | 不暗示真实提交完成 | 只模拟已确认流程，不连接真实业务或外部系统，除非用户另有要求 |

## 9. 后续控件规划

以下控件仅建立候选，不因本参考自动进入每个项目：

- 日期与时间选择、数字步进器、自动完成、级联选择、树选择、穿梭框、标签输入和范围滑块。
- 折叠面板、分段控制、文件预览、拖拽排序、虚拟列表和移动端底部面板。
- 富文本或代码编辑器、命令面板、数据可视化交互等复杂控件。

只有满足以下条件之一时再固化详细规范：项目已确认设计系统提供稳定组件；至少两个独立场景重复使用并形成一致模式；用户明确要求提升为个人标准。单个页面的偶然实现不直接升级为通用规范。

## 10. 验收清单

- 空间来自统一 Token，同级区域没有无依据的间距漂移。
- 标签、控件、帮助、错误和操作区的归属清楚，未用留白制造错误层级。
- 控件类型符合任务语义，Switch、Checkbox、Radio、Select 和 Button 没有互相误用。
- 禁用、只读、隐藏、加载、错误和选中状态可以清楚区分。
- 静态稿没有为凑组件大全扩展无关状态；交互稿实现了本次可到达的状态和恢复路径。
- 弹层、菜单和选择器没有裁切、遮挡、越界或关闭后焦点丢失。
- 控件文案、动作结果和异常反馈可以回溯到已确认需求，未补造业务规则。
