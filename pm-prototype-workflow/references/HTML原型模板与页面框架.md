# HTML 原型模板与页面框架

本参考只规定静态评审结构，不自动选择产品风格。先按主 Skill 明确 project / personal 档案，再载入对应壳层；没有项目来源时不自动回退到任一模板。

## 使用边界

- 用于静态多屏 HTML 视觉评审稿；默认先确认聊天框线框，用户明确要求跳过时记录跳过项。局部修改只处理本次范围，不自动重走完整流程。
- 不用于可交互原型、线上产品代码或 Figma 原生结构；这些场景按主 Skill 对应流程执行。
- 页面框架指信息组织模式，不是前端技术库。项目风格从项目已确认框架起稿，个人风格从[个人模板](个人风格原型模板.html)起稿；既有后台参考仅用于明确采用该风格的项目。标记与记录见[原型风格档案](原型风格档案.md)。
- 静态稿可实现下拉选择、列表左右拖拽和页面上下滚动等轻量演示操作；不实现复杂多步骤联动、真实提交/校验、接口、通知或数据写入。箭头和标注仅表达评审路径。
- 页面壳层、颜色、字体和尺寸服从主 Skill 静态规则及项目规范。模板中的通用类名是默认结构契约，不得在单个页面内重新定义同名类的语义；项目例外必须通过差异表说明。
- 页面、容器和控件的空间档位及控件装配方式遵循 [控件与空间规范](控件与空间规范.md)；静态稿与后续交互稿使用同一套空间 Token。

## 项目框架复用门禁

项目存在已确认公共框架时，本参考中的通用 `.app-shell` 仅表示内容装配位置，不得用来重新搭建近似框架。起稿前必须：

1. 确认项目指定的框架事实源，不从历史稿、截图和不同页面分别提取顶部栏或菜单。
2. 标记锁定壳层与业务内容槽；顶部栏、导航、菜单、页签和公共工具保持事实源结构，业务页面只替换内容槽及当前态。
3. 多个场景复用同一份壳层结构或同一个渲染函数，不在每个场景卡内复制后分别修改。
4. 完整页面必须保留框架事实源的完整公共壳层；弹窗、抽屉、Toast 等组件评审仍只画组件本体。
5. 输出前对比框架事实源，任何不属于本次需求的壳层差异都视为缺陷。
6. 输出前保留一份“锁定壳层 / 可替换内容槽 / 本次差异”记录；没有差异时明确写“无框架差异”。

## 起稿选择

先确定每个场景卡代表的一个页面状态或明确的并列分支，再选一种主要页面框架。仅组合本场景确实需要的区块。

| 页面框架 | 适用内容 | 常见区块顺序 | 不应自动增加 |
| --- | --- | --- | --- |
| 列表/管理页 | 查询、浏览、批量或行级管理对象 | 页面标题 -> 筛选 -> 工具操作 -> 表格/列表 -> 分页 | 未要求的统计卡、批量操作、导出 |
| 详情页 | 查看单个对象及其属性、关联或操作 | 页面标题/返回 -> 状态与摘要 -> 分组信息 -> 关联内容 -> 操作 | 编辑表单、无关指标或额外标签页 |
| 新建/编辑表单页 | 创建或修改对象 | 页面标题/返回 -> 分组字段 -> 字段级操作（如有）-> 底部操作（仅需求要求时） | PRD 未定义的字段、默认值、校验和帮助文案 |
| 工作台/仪表盘 | 需求明确要总览或监控多个指标 | 页面标题 -> 核心指标 -> 图表/趋势 -> 明细或待办 | 为填充空间添加的装饰图表和虚构数据 |
| 组件评审 | 抽屉、弹窗、Toast、结果卡等非整页内容 | 组件标题 -> 内容/字段 -> 操作区或提示本体 | 页面壳层、蒙层、蒙层下页面或背景装饰 |
| 状态评审 | 同一页面/组件的成功、失败、处理中等必要状态 | 按行为、恢复路径和评审需要拆屏，按真实关系排布 | 不适用的状态全集，以及仅因悬停或聚焦而增加的状态屏 |

一个场景卡可以组合列表与弹窗等不同内容作并列评审，但不得把两个互不相关的完整页面挤进同一块内容区域。需要展示两个完整页面或两个组件时，使用主 Skill 定义的对应并列尺寸，并说明它们是分支、对照还是结果。

## 空间与控件装配

- `--space-*` 是布局档位，不要求每个文件全部使用；只保留当前原型实际需要的 Token。项目已有变量命名时映射到项目变量，不同时维护两套值。
- 页面区块优先使用 `--space-6` 或 `--space-8`；独立字段使用 `--space-4` 或 `--space-6`；标签、图标、帮助与错误信息使用 `--space-1` 或 `--space-2`。
- 同一页面中相同层级保持同一档位。需要改变密度时按完整区域调整，不只压缩某一个控件或一行内容。
- `.field`、`.field-group`、`.button-group`、`.btn` 和 `.control` 只是装配钩子；按钮类型、开关语义、选择器状态和弹层行为以 [控件与空间规范](控件与空间规范.md) 为准。
- 静态稿中可见的禁用、错误、加载、选中和打开状态必须来自本次评审范围；不要为了展示模板能力而给所有控件补齐状态全集。

## 页面区块组合规则

- 列表页：筛选字段标签置于控件上方；列表、表头、行操作和分页保持对齐；分页条按 [列表与分页控件](列表与分页控件.md) 装配，区块顺序与列宽按 [列表页装配与列宽](列表页装配与列宽.md) 推算；是否提供新增、导出、批量操作只按 PRD 展示。
- 表单页：字段分组按用户任务顺序组织；字段名称、必填、默认值、即时/提交校验和提示内容以已确认 PRD 为准。静态稿只表达页面外观，不暗示校验真的执行。
- 详情页：先呈现对象识别信息和当前状态，再按业务阅读顺序展示字段组；操作仅保留已定义且当前状态允许的操作。
- 抽屉/弹窗：抽出 `.component-only`，独立放在场景卡中；只画组件本体。标题、字段和按钮遵循主 Skill 的组件规则。
- Toast/结果页：按本次范围展示必要结果；成功与失败、行为或恢复路径不同的状态应清楚区分。处理中能否取消或关闭、失败能否重试，以已确认 PRD 为准，不自行增删操作。
- 组合屏：两个页面或两个组件只有在同一步骤并列对照、不同分支或同一结果比较时才同屏；有先后操作依赖则拆屏并用箭头说明。

## 轻量演示操作

静态原型可以加入少量局部操作，方便现场讲解和视觉评审；操作应可逆、就地生效，并且不暗示真实业务已完成。

| 操作 | 可实现的演示效果 | 边界 |
| --- | --- | --- |
| 下拉选择 | 展开选项、选中一个选项并显示当前值 | 选项和值必须来自已确认需求；不据此触发跨页面或多步骤业务联动 |
| 列表左右拖拽 | 在当前画面内调整条目顺序或横向查看内容 | 仅为本地展示，不保存排序或修改业务数据 |
| 页面上下滚动 | 使用自然页面滚动查看超出当前视口的内容 | 不用滚动隐藏必要字段、状态或操作 |

这类操作可用原生控件或少量本地脚本实现，尽量减少依赖；离线交付所需资源应随文件提供或内联，业务跳转链接另按需求处理。不得扩展成跨步骤的条件联动、真实校验、提交结果推导、持久化或外部系统行为；若用户要求完整可操作流程，应切换到可交互原型模式并重新确认范围。

## 箭头和导航

- 屏内 `id` 使用稳定屏号（如 `scene-1a`）；箭头目标必须与屏号对应。
- 每条跨屏箭头标出“触发动作 + 条件/分支 + 可观察结果”，例如：`点击「保存」· 校验通过 → 展示成功结果`。
- 静态原型用“曲线连接器”表达跨屏流转，不用纯文字流转框，也不用悬在中间的小箭头符号：起点圆点贴来源卡底边、终点实心三角贴目标卡顶边，触发说明钉在曲线上。说明只写触发与结果，不写屏号——箭头已经表达方向。

  ```html
  <div class="flow" data-from="2c" data-to="2d" style="height:180px">
    <svg class="flow-curves" viewBox="0 0 2240 180" width="2240" height="180" aria-hidden="true">
      <path d="M1697 5 V31 C1697 64 543 96 543 130 V158"/>
      <polygon points="543,180 531,158 555,158"/>
      <circle cx="1697" cy="5" r="5"/>
    </svg>
    <div class="flow-note" style="left:1120px;top:84px">点击「继续解析」· 解析结束 → 展示解析结果</div>
  </div>
  ```

  ```css
  .flow { position: relative; width: 2240px; margin: 0 auto; }
  .flow-curves { position: absolute; left: 0; top: 0; display: block; pointer-events: none; }
  .flow-curves path { fill: none; stroke: #5f6b7c; stroke-width: 3; stroke-linecap: round; }
  .flow-curves polygon { fill: #39424f; }
  .flow-curves circle { fill: #5f6b7c; }
  .flow-note {
    position: absolute; transform: translate(-50%, -50%);
    padding: 3px 10px; background: #fff; border: 1px solid #E3E8EF; border-radius: 7px;
    font-size: 12px; line-height: 18px; color: #5B6472; text-align: center; white-space: nowrap;
    box-shadow: 0 1px 3px rgba(16,26,44,.06);
  }
  .flow-note .flow-sub { display: block; font-size: 11px; line-height: 16px; color: #8A929E; }
  ```

- 坐标规则：画板固定 `2240px`，连接器按整板绝对坐标绘制。列中心单卡为 `1120`，并排两卡为 `543 / 1697`；圆点 `r=5`，三角为 `(x,y) (x-12,y-22) (x+12,y-22)`。
- 起止点必须实测，不能按 `flow` 容器推算：并排两卡高度不同时，`flow` 顶对齐的是较高那张卡的底边，另一张卡的圆点会悬空 `100~260px`；`flow` 与下一行之间还夹着组标签，箭头也会整体偏移约 `40px`。做法是用无头浏览器读到每个屏卡的 `getBoundingClientRect()`，按实测值生成路径：圆点 `cy` = 该来源卡底边在 `flow` 坐标系中的位置，三角顶点 = 目标卡顶边；需要向上溢出时给 `svg` 负 `top`，并把 `viewBox` 起点设为同一个负值，高度按实际跨度给到 `140~480`。
- 走线分三段：26px 竖直引出 → 三次贝塞尔斜移（控制点在 34% / 66% 处）→ 26px 竖直落入，箭头始终垂直朝下。竖直段必须保留，`.flow-note` 压线处才不会是斜线的锐角。
- 四种拓扑都按实际路径画，各自配一条说明，不合并成一句话：单线（一源一目标，取曲线中点）；合流（两源一目标，两条曲线汇到主干后共用一支箭头）；分叉（一源两目标，同一起点分两路）；交叉（两源两目标，X 形，两条线各落到自己的目标卡）。
- 说明落点取曲线参数位置：单线与分叉 `t=0.5`，合流取汇合后主干 `t≈0.35`，交叉两条各取靠起点侧的 `t=0.25`（两条都取中点会互相压字）；再兜一条下压规则——说明中心距上一行卡底不小于 `32px`，否则长尾段的中点会落进上方卡片。
- 连接器只能连紧邻上一行到紧邻下一行。跨行或旁支回流不硬画线，改为来源行底部的 `↘ 见下屏 2b`（`.row-note`）或右对齐回退注 `.back-note`。
- 并排必须带组标签，写明关系类型：

  ```html
  <div class="group-tag w2164"><span>同屏页签 · 解析结果（成功 / 失败）</span></div>
  <div class="row pair w2164">
    <article id="scene-2d">…</article>
    <div class="pair-mid"><b>⇄</b></div>
    <article id="scene-2e">…</article>
  </div>
  <p class="back-note w2164">↩ 5b 重试结束回 5a；5d 为 5c 的失败页签</p>
  ```

- 指向并排行的连接器，箭头顶点仍顶在目标卡顶边，不从组标签上沿截断；组标签只占行高，不参与连接器坐标。
- 并排关系符号：有先后的两态用横向箭头（`.pair-arrow`），同屏页签用 `⇄`，无先后的并列用 `∥`。来源不同且无先后的两屏不得并排，拆成上下两行。
- 同屏页签（成功 / 失败）与口径对照属并列，不加纵向箭头，在屏头写明“X 的失败页签”。
- 回退与循环不单独占行，写成 `.back-note` 右对齐小字，随来源行一起移动。
- 箭头仅供评审阅读，不实现点击跳转。上一页/下一页或屏号目录属于评审导航时，应与产品界面视觉区隔，不得伪装成产品操作；用户要求纯静态画面时可以不加导航。
- 并列分支从共同来源分叉并同排展示，宽度按内容与主次分配，不固定比例；仅真实先后状态使用纵向串联。无业务流转关系的对照不连箭头。

## 结构与样式手法

- **一屏一卡，屏信息包裹页面**：`.scene` 白底 + `1px #E3E8EF` 描边 + `14px` 圆角 + 轻投影 + `overflow: hidden`；`.scene-head` 作卡头（屏号展示区），`#F8F9FB` 底 + `1px #EAEEF3` 分隔线，`padding: 12px 16px 13px`，grid 两行（屏号与标题一行、入口说明一行），高度约 `70px`；`.scene-canvas` 零内边距；页面自身去掉描边、圆角、阴影和底色，直接当卡体。不要用“白色信息条 + 白色页面卡”两层白块叠加。
- **并排等高**：`.row.pair { align-items: stretch }`，并打通 flex 链——`.scene`（本身 flex column）→ `.scene-canvas { display: flex; flex-direction: column }` → `.scene-canvas > .modal { flex: 1 1 auto }` → `.modal-body { flex: 1 1 auto }`。这样同一行的卡头齐平、底边也齐平，连接器起点落在同一条基线上。不要用 `align-items: flex-end`：那会让较矮屏的卡头跟着下沉。
- 卡底色与页面底色相同时，靠卡头灰底 + `1px` 分隔线区分层级，不额外加阴影；页面自身的框线一律去掉，避免双层描边。
- 并排较矮的屏在框内保留自身留白（页面白底延伸），不拉伸内容、不居中、不贴底。

## 绘制与验证技巧

连接器、居中与对齐都不靠估算，按以下顺序做：

1. **先量后画**：用 headless Chrome 注入探针脚本，`window.load` 后读取每个 `.scene`、`.flow`、`.flow-note` 的 `getBoundingClientRect()`，把结果写进 `<pre>`，再用 `--dump-dom` 取回 JSON；按实测值生成 SVG 路径，而不是按容器高度推算。
2. **截图必须 1:1**：`--force-device-scale-factor=1` + 固定 `--window-size`，用 `body { position: relative; left: -Xpx; top: -Ypx }` 平移取景。不要用 `zoom` 或 `transform: scale()` 缩放整页（高页面会被浏览器整体缩掉），`sips --cropOffset` 与 `-c` 的顺序会变成居中裁切，同样不可靠。
3. **整版缩略**用 `body { zoom: .32 }` + 高窗口一次成像，只用于看纵向节奏，不能用于测量坐标。
4. **自动断言四件套**：① 每个圆点相对其来源卡底边偏差为 `0`，每个三角顶点相对目标卡顶边偏差为 `0`；② 每条说明块中心到曲线的最近距离 ≤ `3px`；③ 说明块不压任何屏卡、彼此不重叠；④ 沿路径采样 300 点，不落在任何屏卡矩形内（留 `2px` 容差）。
5. **脚本陷阱**：正则替换 `d="…"` 会误伤 `data-page-node-id="…"` 末尾的 `d="`，改用 `(?<![-\\w])d="`；`<p[^>]*>` 会吃掉 `<path>`，写成 `<p(?=[\\s>])[^>]*>`；`</div>` 是 6 个字符，配对时按 4 个算会残留尾巴。
6. **在副本上迭代**：结构与配色的多轮试改都在临时副本里做，断言全绿后再一次性写回原型，避免原型停留在中间态。

## 自检

- 场景卡屏号稳定、唯一，屏名与箭头目标一致；交付说明从原型整理，PRD 不重复维护完整屏清单；画布页头没有屏号列表或图例。
- 每屏只表达一个状态或一个明确的并列场景；页面/组件尺寸符合主 Skill 的场景尺寸表。
- 非整页组件没有蒙层、蒙层下页面或背景衬托；产品界面与评审标注分开，保留已确认的字段帮助、格式提示、风险和错误提示。可见内容不写内部需求编号、章节引用或视觉规格，代码和非可见追溯信息不受此限制。
- 未引入 PRD 未定义的字段、业务规则、默认值、操作、数据或状态。
- 轻量操作仅改变当前展示，不持久化、不触发复杂联动，也不伪装成真实业务处理；含脚本时核对关键元素、实际演示操作和状态结果，检查运行时错误。
- 静态、浏览器操作和视觉证据分别报告；未执行或受阻的检查写明限制，截图不能替代操作结果检查。
- 区块宽度稳定，无重叠、裁切和文字溢出；窄屏可调整间距，但不能隐藏字段或打乱并列分支。
- 页面、容器、字段和控件内部的空间层级清楚，同级区域使用一致 Token；按钮、输入、选择、开关、弹层和反馈控件符合控件与空间规范。
- 项目存在框架事实源时，顶部栏、左侧导航、菜单顺序、功能页签、全局工具和工作区偏移与事实源一致；每个完整页面只替换业务内容槽，不存在按屏重画的壳层变体。
