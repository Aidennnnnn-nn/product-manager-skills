# 本地插件调用规范

## 素材来源选择

绘制或更新 Figma 原型前，先读取 `references/设计参考资料使用规范.md`，从公开设计参考中选择 1-3 个匹配来源，再进入 HTML 调整。

如果公开参考无法覆盖需求，可以使用补充来源，但必须在 `原型数据.json`、HTML 注释、交付说明或 Figma 说明层中标记为“补充来源”并说明原因。

## HTML 优先流程

后续绘制或更新 Figma 原型时，先把设计调整落到本地 HTML，再由本地插件同步到 Figma。

推荐顺序：

1. 选择设计参考来源。
2. 查找或创建 HTML 原型源文件。
3. 在 HTML 中完成页面结构、文案、布局、样式、组件状态和响应式约束。
4. 本地预览 HTML，确认没有文本溢出、遮挡、错位和状态缺失。
5. 将 HTML 中稳定下来的结构、token、素材来源或配置交给本地 Figma 插件。
6. 运行插件，把 HTML 原型输入或同步到 Figma。
7. 对比 Figma 输出和 HTML 源文件；如设计有问题，先回到 HTML 修改，再重新同步。

推荐文件位置：

```text
交付素材/<主题>_<日期>/原型预览.html
交付素材/<主题>_<日期>/原型数据.json
交付素材/<主题>_<日期>/<插件名>/manifest.json
交付素材/<主题>_<日期>/<插件名>/code.js
```

如果插件已有 `ui.html`，先判断它是插件面板 UI 还是原型源文件。不要把插件面板 UI 误当成最终原型，除非它本身就是用户确认过的 HTML 原型。

## HTML 到 Figma 的输入契约

本地插件同步 Figma 时，优先使用可追踪的输入契约：

- HTML/CSS 是视觉和内容源。
- CSS 变量或 JSON 作为颜色、字号、间距、圆角等 token 来源。
- `原型数据.json` 建议包含 `materialSources`、`fallbackSources`。
- 页面、画板、组件、文本、状态以结构化配置传给 `code.js`。
- Figma 图层命名尽量沿用 HTML 中的页面名、区块名和组件名。
- Figma 页面或说明图层保留“设计参考来源说明”，列出采用的公开参考和补充来源。

`原型数据.json` 最小字段示例：

```json
{
  "projectName": "示例原型",
  "materialSources": ["Apple iOS / iPadOS UI Kit", "Material 3 Design Kit"],
  "fallbackSources": []
}
```

可选实现方式：

1. 从 HTML 手动整理出 `原型数据.json`，插件读取或内置该配置。
2. 在 `code.js` 中维护从已确认 HTML 抽取的结构化对象。
3. 在插件 `ui.html` 中提供粘贴 JSON 的入口，再由插件写入 Figma。

不要把 Figma 画布上的临时手工修改作为新的唯一事实来源。若 Figma 与 HTML 不一致，先判断 HTML 是否需要更新；确认后再改插件映射逻辑。

## 查找插件

优先在当前工作区查找：

```bash
rg --files -g 'manifest.json'
```

常见位置：

```text
交付素材/*/manifest.json
交付素材/*/*/manifest.json
```

读取 `manifest.json` 后确认插件名称和菜单命令，例如：

```json
{
  "name": "通用原型绘制插件",
  "main": "code.js",
  "ui": "ui.html",
  "menu": [
    { "name": "按HTML绘制原型", "command": "draw-from-html" },
    { "name": "绘制移动端登录页", "command": "quick-mobile-login" }
  ]
}
```

## 新增插件命令

新增菜单命令时同时改两处：

1. `manifest.json`

```json
{ "name": "清理重复页面", "command": "cleanup-duplicate-pages" }
```

HTML 同步类命令示例：

```json
{ "name": "按HTML绘制原型", "command": "draw-from-html" }
```

2. `code.js`

```js
if (command === 'cleanup-duplicate-pages') {
  // 执行清理逻辑
  figma.closePlugin('已清理重复页面');
  return;
}
```

HTML 同步类命令应从已确认的 HTML 配置或 token 生成画布：

```js
if (command === 'draw-from-html') {
  var prototype = getApprovedHtmlPrototypeData();
  drawPrototypeFromData(prototype);
  figma.closePlugin('已按HTML原型同步到Figma');
  return;
}
```

修改后运行：

```bash
node --check code.js
```

再在 Figma 桌面端执行：

```text
Plugins -> Development -> Hot reload plugin
```

## 重复页面清理建议

清理重复页面前先盘点：

- 按 `page.name` 完全匹配分组。
- 每组只保留页面列表中最靠上的第一个。
- 删除同名页面的后续副本。
- 删除前向用户列出：保留哪一个、删除几个、删除哪些页面名。

推荐插件逻辑：

```js
function collectDuplicatePages() {
  var groups = {};
  figma.root.children.forEach(function (page, index) {
    if (!groups[page.name]) groups[page.name] = [];
    groups[page.name].push({
      id: page.id,
      index: index + 1,
      name: page.name,
      childCount: page.children.length,
    });
  });

  return Object.keys(groups).filter(function (name) {
    return groups[name].length > 1;
  }).map(function (name) {
    return {
      name: name,
      keep: groups[name][0],
      remove: groups[name].slice(1),
    };
  });
}
```

删除当前打开页面前，应先切到保留页：

```js
if (typeof figma.setCurrentPageAsync === 'function') {
  await figma.setCurrentPageAsync(keepPage);
} else {
  figma.currentPage = keepPage;
}
```

## Figma 桌面端调用

使用 Computer Use 操作 Figma：

1. `get_app_state` 读取当前窗口。
2. 打开 `Plugins` 菜单。
3. 进入 `Development`。
4. 选择目标插件和命令。
5. 运行后再次 `get_app_state` 验证页面列表或图层列表。

如果普通点击菜单不稳定，可优先使用菜单项的辅助动作 `Pick`。

HTML 同步任务常用菜单名：

```text
Plugins -> Development -> 插件名 -> 按HTML绘制原型
Plugins -> Development -> 插件名 -> 同步HTML到Figma
Plugins -> Development -> 插件名 -> 导入HTML配置
```

运行后检查：

- Figma 页面名是否与 HTML 原型页面一致。
- 核心文案是否一致。
- 画板尺寸、区块顺序、主色、字号层级是否对齐。
- HTML 中的关键状态是否有对应画板、组件变体或注释表达。
- 页面或说明图层是否保留“设计参考来源说明”。

## DevTools 排查

打开：

```text
Plugins -> Development -> Show/Hide console
```

重点看这些错误：

- `An error occurred while loading the plugin environment`
- `jsvm-cpp.js.br Failed to load resource`
- `ERR_CONNECTION_CLOSED`
- `Livegraph Connection closed`
- 插件自身 `console.error`

如果 DevTools 显示插件环境加载失败，通常不是插件业务代码已执行失败，而是插件运行环境没有启动。先处理 Figma 连接、Developer VM、Hot reload，再重试命令。

## 本地默认路径的 MCP 边界

进入默认本地插件或桌面端写入路径后，执行该次本地同步时不要同时调用：

```text
mcp__figma.get_metadata
mcp__figma.get_design_context
mcp__figma.use_figma
mcp__figma.get_screenshot
```

如果用户改为要求远程 MCP，停止本地插件写入，说明切换影响并重新确认目标节点范围后再执行，避免同一范围产生重复页面或图层。
