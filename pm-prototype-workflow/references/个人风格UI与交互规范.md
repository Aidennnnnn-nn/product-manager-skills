# 个人风格 UI 与交互规范

适用范围：已选择 `personal` 档案的原型。本文登记 personal 的组件样式、状态表达与静态/交互边界，不定义业务语义、状态覆盖策略、校验时机、焦点与键盘规则——这些沿用[控件与空间规范](控件与空间规范.md)、主 Skill「共用 UI 规则」与「首版交互基线」。视觉值唯一维护源仍是 `../assets/个人风格Token.json`，本文不新增色值、字号或尺寸。

[个人风格原型模板](个人风格原型模板.html) 是完整页面的唯一起稿源；[个人风格组件状态样例](个人风格组件状态样例.html) 是组件状态的独立样例，[组件状态预览](个人风格组件状态预览.png) 用于视觉核对；[默认预览](个人风格原型模板_默认预览.png) 只呈现 1a 产品界面。组件的允许名称、变体和状态以 [个人风格组件契约](../assets/个人风格组件契约.json) 为机器可读事实源，本文不再通过近似类名扩展组件清单。

## 1. 组件登记（保留清单）

下列组件已登记在模板和组件契约中，绘制时整体复制、按需求替换内容，不重写近似外观，也不为凑齐清单增加业务功能。页面中的正式组件必须同时带有 `data-component` 和 `data-variant`；未登记组件或变体会被严格审计拦截。

| 组件 | 模板类名 | 锁定要点 |
| --- | --- | --- |
| 主操作 / 次操作 / 危险 / 图标按钮 | `data-component="button"` + `data-variant="primary/default/danger/icon"` | 高度、圆角、边框、文字色与背景取自 Token；主操作为品牌绿底深字 |
| 输入、选择与字段标签 | `data-component="control/field"` | 高度、圆角、下沉底色、标签字号；占位用「请输入」 |
| 开关 | `data-component="switch"` + `data-variant="on/off/disabled"` | 尺寸、圆点、开/关两态；只表达即时二元切换 |
| Checkbox / Radio | `data-component="choice"` + `data-variant="checkbox/radio/disabled"` | 尺寸与选中色；标签整体可点击 |
| 页签 | `data-component="tabs/tab"` + `data-variant="active/default/disabled"` | 文字 + 底线区分当前态 |
| 筛选区 | `data-component="filters"` + `data-component="field/control"` | 标签在上、控件在下；查询在前、重置在后 |
| 表格与分页 | `data-component="table/pagination"` | 表头、行分隔、行操作文字、页码序列 |
| 状态标签与文字按钮 | `data-component="status-label/button"` | 辅助字号；状态不只靠颜色 |
| 成功 / 失败反馈 | `data-component="notice"` + `data-variant="success/failure/warning/loading"` | 图标 + 文案，静态评审只画组件本体 |
| 确认弹窗 | `data-component="confirmation"` + `data-variant="default/loading"` | 标题、说明、取消与危险操作、关闭按钮 |
| 卡片、指标与列表项 | `data-component="panel"` | 面板圆角、细边、阴影与分组间距 |
| 窄侧栏与工作区页头 | `data-component="sidebar/nav-item/workspace-header"` | 锁定壳层，见[原型风格档案](原型风格档案.md) |

模板内菜单、表格、指标和示例对象只演示布局，不代表需求。未列入组件契约的抽屉、Sheet、Toast、Tooltip、Popover、上传、进度与空状态不得直接使用；需要时先登记组件契约、模板样例和审计规则，再进入业务原型。

## 2. 状态矩阵

| 状态 | personal 下的表达 | 静态评审稿 | 可交互原型 |
| --- | --- | --- | --- |
| 默认 | 模板默认样式 | 必画 | 必实现 |
| Hover | 主操作用 `--brand-hover`；其余用边线或阴影的轻微变化 | 仅当本身是评审重点 | 适用控件实现 |
| Focus-visible | `--focus` 描边，不与浏览器原生外框叠加 | 仅当本身是评审重点 | 必实现 |
| 按下 | 位移与阴影收敛，不改语义色 | 通常不画 | 适用控件实现 |
| 选中 / 当前 | `--brand` 底或底线，配合文字或结构差异 | 必画 | 必实现 |
| 禁用 | 下沉底色、`--subtle` 文字与降透明度 | 需要评审时 | 必实现且阻止触发 |
| 只读 | 保留值、淡化文字、弱化边线 | 需要评审时 | 保持不可编辑 |
| 加载 | 主按钮锁定防重复，配文字或图标提示 | 需要评审时 | 必实现并恢复 |
| 错误 | `--danger` 边线 + 字段附近文字说明 | 需要评审时 | 必实现且可恢复 |
| 打开 / 关闭 | 弹层本体与遮罩；弹窗沿用 `.confirmation` | 独立屏或局部演示 | 触发、外部点击、`Escape`、关闭按钮、焦点返回 |

状态不得只依赖颜色，必须同时提供文字、图标、形状或结构差异。3a 状态样例带 `data-state-sample` 标记，只作样式核对，不是产品功能，也不参与锁定校验；不得用状态样例绕过产品界面的锁定检查。

## 3. 弹窗、抽屉与反馈

- 确认弹窗沿用模板 `.confirmation` 的标题、说明与操作区；触发条件、关闭路径与焦点返回沿用主 Skill「首版交互基线」，本文件不重复定义。
- 抽屉 / Sheet / Toast / Tooltip / Popover 暂无模板样例：绘制时沿用同一 Token 与现有面板、反馈组件的样式，先在本文件与模板登记后再使用，不自行新画一套视觉。
- 组件独立样例屏不是页面中的额外产品功能；静态评审只画组件本体。

## 4. 静态与交互版

| 维度 | 静态评审稿 | 可交互原型 |
| --- | --- | --- |
| 结构与 Token | 与模板一致，复用同一份壳层 DOM 与 Token | 与静态稿一致 |
| 状态范围 | 只画本次需评审的状态，用 3a 状态样例核对样式 | 实现本次流程可到达的状态 |
| 行为 | 不暗示真实提交或加载完成 | 只模拟已确认流程，不连真实业务或外部系统 |
| 焦点与键盘 | 不要求完整模拟 | 检查适用键盘操作、初始焦点与焦点返回 |

静态与交互原型采用同一 DOM 与视觉 Token，区别只在授权范围内的行为深度；升级交互版不换档案。细则见[控件与空间规范](控件与空间规范.md)第 8 节。

## 5. 校验与交付

- 新建或明确重画的个人风格稿件运行 `node scripts/audit.mjs <原型.html> --strict --require-style --require-components`；状态样例节点带标记，校验只作用于产品默认态节点。
- Skill 包本身先运行 `node scripts/validate-skill-package.mjs`；组件契约、模板、Token 和图标清单任一不一致，都不能把原型标记为可交付。
- 交付说明分别报告：组件登记覆盖、状态覆盖、锁定壳层差异、图标与资源检查、浏览器加载检查与视觉回读结果。
- 视觉截图不替代结构或行为证据；模板与预览图的样式变更须同步本文、`../assets/个人风格Token.json` 的校验条目与 `CHANGELOG.md`。
